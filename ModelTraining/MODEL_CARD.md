# 앱에 연결된 모델 · 2026-09-06

## 음식 종류

`MealLens/FoodClassifier.mlmodel`은 기존 Food-101 101종 분류기입니다. Create ML Scene Print V2 + 로지스틱 회귀로 학습했습니다. 기존 시험 사진 1,515장의 원본 기준 Top-1 65.8%, Top-3 83.2%입니다. 같은 사진을 384px JPEG로 정규화한 이번 비교에서는 Top-1 66.4%, Top-3 82.8%입니다. **전처리가 다른 두 수치의 차이는 재학습 효과가 아닙니다.**

한식 150종을 포함한 251종 학습은 원본 중복·상충 라벨 검사와 51,191장 준비를 마쳤지만 Create ML 내부 오류로 완료되지 않았습니다. 정규화, ASCII 경로, Scene Print revision 1/2를 각각 시도했습니다. 따라서 앱의 음식 분류기가 한식 150종을 새로 학습했다는 뜻은 아닙니다.

## 사진 속 접시 전체의 중량·열량

`MealLens/PhotoGrams.mlmodel`, `MealLens/PhotoCalories.mlmodel`은 이번에 새로 학습했습니다. [Nutrition5k](https://github.com/google-research-datasets/Nutrition5k)의 위에서 촬영한 RGB 사진과 접시별 실측 중량·영양정보를 사용합니다. Vision feature print revision 2 / centerCrop의 768차원 특징을 입력받는 Create ML boosted-tree 회귀기입니다. 예측한 로그값을 지수 변환해 g/kcal로 사용합니다.

- 학습 2,100장 / 검증 654장 / 시험 506장.
- 공식 depth train/test 분할을 유지합니다. 학습 집합 중 촬영일의 Unix 일수 나머지가 0인 날을 검증에 배정합니다(5일 기준).
- 공식 목록 중 칼로리 0인 샘플 2장, RGB가 없는 샘플 3장을 제외했습니다. 이미지 SHA-256 중복은 없습니다.
- 최대 120회, 깊이 4, 학습률 0.08, seed 42. 검증 오차로 early stopping하며 시험 데이터로 조정하지 않았습니다.

| 시험 지표 | 학습 집합 중앙값만 사용하는 기준 | 원본 RGB 모델 | 앱 전처리를 포함한 모델 |
| --- | ---: | ---: | ---: |
| 중량 평균 절대 오차 | 115.4g | 50.1g | **52.9g** |
| 열량 평균 절대 오차 | 167.3kcal | 87.2kcal | **87.5kcal** |

기준값은 중량 180g, 열량 206.96kcal입니다. 이는 이전 앱의 음식별 대표량과 직접 비교한 결과가 아닙니다. 앱 전처리 평가는 실제 `PhotoPreparation.prepare` → `PhotoPortionInference.estimate` 소스를 macOS에서 실행했습니다. iOS 테스트는 별도로 런타임 호환성을 확인하며 이 표는 iPhone 실사진의 정확도가 아닙니다.

재윤의 iPhone에서 번들 모델 2개의 실행과 서로 다른 합성 이미지에 대한 예측 변화 테스트를 통과했습니다. 시뮬레이터 테스트 15개, 데이터 준비 테스트 7개도 통과했습니다. 합성 이미지 테스트는 음식 정확도 평가가 아닌 실행 호환성 검사입니다.

사진 전체의 중량·열량만 학습했습니다. 음식별 분할, 깊이 측정, 재료 확인, 탄수화물·단백질·지방 회귀를 수행하지 않습니다. 앱의 매크로는 여전히 음식별 예시 영양값과 추정 중량으로 계산하므로 열량 회귀와 정확히 일치하지 않을 수 있습니다. 중량을 사용자가 수정하면 표시된 영양 밀도로 비례 환산합니다.

모델은 미국 캘리포니아 구내식당의 촬영 장치 데이터로 학습했습니다. 한식 국·찌개, 스마트폰의 각도·조명·용기·크기 변화는 검증하지 않았습니다. 입력 음식이 학습 분포에 속하는지 거부하는 기능도 없습니다. 기기에서 작동하는 실험적 추정값이며 실제 중량 측정이나 의료용 영양 분석을 대체하지 않습니다. 모델을 실행하지 못하면 음식별 대표량을 사용하고 화면에 그 출처를 표시합니다.
